# Usage

`--json` on any verb prints one envelope `{ code, exit, reason, message, warnings, data }`. Exit:
0 ok, 1 failed, 2 bad call, 4 something missing.

```bash
qsm-builder lens [dir] [--port 4747]
qsm-builder lens export [dir] --out lens.html
qsm-builder lens readme [dir] [--check]
qsm-builder lens pull <artifact-url>
qsm-builder lens tasks [plugin]
qsm-builder lens brief <file>
qsm-builder lens marketplace [--dir <root>]
qsm-builder lens plugin <name> [--dir <root>]
qsm-builder doctor
```

- `lens export` reads the marketplace in `dir` (default: the working directory) and writes one
  self-contained HTML page: an overview tab and one tab per plugin with why it exists, skills,
  agents, eval cases, CLI verbs, hooks and the names it refers to. Open it in a browser; tabs switch
  by the URL hash (`#plugin-<name>`). Nothing is generated by a model and no plugin file is written.
- `lens readme` writes `assets/lens-banner-light.svg`, `assets/lens-banner-dark.svg` and the text of
  the root README between `<!-- lens:start -->` and `<!-- lens:end -->`: banner, what it is, the
  overview graph, a catalog table per kind of plugin, and how to open the lens. A plugin's kind is
  the first of core (`essentials`), planning (`tasks`, `openspec`, `planning`), code quality and
  languages (`langdev`, `code-review`, `secrets`), knowledge and web (`knowledge`, `research`,
  `web`) that names one of its `keywords` in plugin.json; every other plugin is tooling. Text
  outside the markers stays. `--check` writes nothing and exits `worse` (3) naming each file that
  differs; `bun run validate` runs the same check. A README without both markers exits 4.
- `lens` serves the same page on `127.0.0.1` (default port 4747, `--port 0` picks a free one),
  rendered from the repository on every request. It watches the marketplace (not `.git`,
  `node_modules`, `.qsm`, `.claude`, `dist` or `evals/results`) and tells the open page over one
  event stream, so the page redraws with no reload. A taken port exits 1 (`failed`) and names it.
  The names a graph looks for are `plugins/qsm-builder/references.txt` in the marketplace shown,
  else the copy built into the binary.
- On the served page a small pen at the top right of each text read from the marketplace turns that
  text into its control (input, select or text box) with a note box. Save makes one task in the task
  tool of the marketplace, titled `<plugin>: <what>` or `<plugin>:<item>: <what>`; its description
  holds the file, the section, the file's sha256 when the page was rendered, the text before, the
  text after and the note. No plugin file is written. A task whose file no longer has that sha256 is
  shown `stale` and is never applied as is. The exported page carries the pens too, hidden until it
  runs as a published artifact with its database; opened from disk it is read-only and says where
  edits are made.
- A page that can save edits also has a new-item page, linked from the overview (`#new`): a form
  for a new skill, agent or plugin with its use case, trigger words, model, tools, CLI, links and
  one eval case, and a button that checks the words against what already exists. Save makes one
  task of kind new, titled `<plugin>: new skill <name>` (`marketplace: new plugin <name>`), with
  `kind: new` and the file the item would start in. It is refused without an eval case ("what the
  eval does", "what the grader expects") and when that file exists. Nothing is created; the
  `add-plugin` skill takes the task from there. A new task is shown `stale` once its file exists.
- `lens pull <artifact-url>`, run in the marketplace, reads the rows the published page saved
  (collection `edits`) and makes one task per untaken row, the same task the served page makes,
  then marks the row taken, so a second pull makes none. A row naming no plugin of this marketplace
  is refused, named, and left untaken. A row whose task was made but which could not be marked taken
  exits 1 (`failed`) and names the row. The rows are read through `claude -p` (haiku, ArtifactData
  only): exits 4 without `claude`.
- `lens tasks [plugin]`, run in the marketplace, lists a plugin's open tasks: its own (title
  starting `<plugin>:` or the name without `qsm-`, as `web:`) and the ones that name it. Each line
  is plugin, id, kind (`edit`, `new`, `feedback`, `task`), `stale`, `current` or `-`, and the title.
  An edit is stale when its target file no longer has the sha256 recorded in the task; feedback is a
  task labelled `source:*`. Without a plugin, each task is listed once under its own plugin. Exits 4
  without the task tool, 2 for a plugin the marketplace does not list.
- `lens brief <file>` takes an absolute path under `<marketplace>/plugins/<name>/` and prints
  that plugin's open edits and feedback (at most ten), or no text when the file is in no plugin of a
  marketplace or the plugin has none. A relative path exits 2, no task tool exits 4. The hook below
  calls it.
- `lens marketplace` prints the whole marketplace as data: its Why it exists and each plugin with
  the first sentence of its own, its dependencies and its count of open tasks.
- `lens plugin <name>` prints one plugin as data: its Why it exists, each skill and agent with
  its description and trigger words, its dependencies with the spec's reasons, its open tasks. A
  name the marketplace does not list exits 2.
- `dir` without `.claude-plugin/marketplace.json` exits 4 (`missing`) and names the file.
- A case's last result is read from `evals/results/<run>/aggregate-result.json`; without one the
  page says so. Open tasks come from the task tool matched by the `<plugin>:` title prefix;
  without it the page says tasks were not read.
- `doctor` checks the binary runs and the task tool is on `PATH`; without it it exits 4 (`missing`)
  and names `qsm-tasks`.

From a hooks module: `$.builder.lensExport({ dir, out })`, `$.builder.lensBrief({ file })`.
The hook adds `lens brief` to the context the first time in a session the agent reads, writes or
edits a file of a plugin, once per plugin.
